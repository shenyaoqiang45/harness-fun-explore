# 关键词星图探索 MVP

[English README](README.md)

## 产品设计理念

这是一个“人机共创的探索系统”，不是传统搜索框。
用户输入一个关键词后，系统不会立刻给出单一答案，而是与用户一起逐轮澄清问题边界：
先扩展、再筛选、再确认、再递归，最终形成可解释的认知路径。

我们的核心信念是：

1. 好问题比快答案更重要
2. 可视化关系比线性列表更能启发思考
3. 过程透明比“黑箱聪明”更值得信任

## 设计北极星

帮助用户从“模糊想法”走到“可执行方向”，并且让这个过程可见、可回放、可复盘。

衡量标准不是一次命中，而是：

1. 用户是否更快收敛到真正关心的主题
2. 用户是否能理解系统为什么给出这些关键词
3. 用户是否能在回看轨迹时复用这次思考路径

## 体验原则

### 1) 递归澄清，而非一次性检索

每轮固定流程：

1. 用户给出当前关注点
2. 大模型扩展最相关的 10 个候选关键词
3. 系统基于全网证据按综合评分选出 Top 5
4. 以树状关系可视化给用户确认
5. 用户点击任意节点继续下一轮

### 2) 人在回路中，用户始终有控制权

1. 用户决定下一轮从哪个节点展开
2. 用户可随时确认终止，冻结最终路径（Shift+点击选中节点，再点 Confirm Path）
3. 系统提供建议，不替用户做不可逆决策

### 3) 可解释优先

每轮都展示：

1. 方向摘要：模型认为用户当前在往哪个方向收敛
2. 用户画像假设：模型对用户目标阶段性的理解
3. 证据依据：关键词入选的信号来源与评分构成

## 轨迹可视化理念

轨迹不是日志页，而是“思考地图”。

我们记录并展示两类核心事件：

1. 大模型输出事件：扩展词、方向摘要、画像判断
2. 工具调用事件：检索、打分、排序、状态返回

轨迹需要满足三件事：

1. 可追踪：任意结果都能回溯到对应事件链
2. 可联动：点击轨迹可高亮树节点；Ctrl+点击树节点可过滤同轮轨迹
3. 可复盘：用户能理解每次分叉为何发生

## 视觉语言：星图观测

整体视觉采用“神秘探索”氛围，强调发现感与方向感：

1. 暗蓝深空背景，建立未知感
2. 金色轨道连线，表达推理路径
3. 冷白高亮节点，突出当前关注点
4. 轻量星尘动效，传达每轮推进的节奏

## MVP 边界

MVP 只验证最关键闭环：

1. 输入关键词 → 10 候选 → Top 5 建树 → 用户递归点击
2. 每轮展示方向摘要、用户画像与证据评分
3. 完整记录模型输出与工具调用轨迹，并在 UI 可见且与树联动

## 快速开始

```bash
npm install
npm run dev    # 自动 build 并启动 http://localhost:3000
npm test
```

复制 [.env.example](.env.example) 为 `.env`，配置 `KIMI_API_KEY` 或 `MINIMAX_API_KEY`。未配置时服务启动即报错。叶节点热度来自 [OpenAlex](https://openalex.org) 学术计量 API（发文量、被引、趋势、共现词）。

## Kimi 接入

1. 设置 `KIMI_API_KEY`
2. 可选 `KIMI_BASE_URL`、`KIMI_MODEL`
3. `sk-kimi-` 前缀自动使用 `https://api.kimi.com/coding/v1`

## MiniMax 接入

1. 设置 `LLM_PROVIDER=minimax` 与 `MINIMAX_API_KEY`
2. 可选 `MINIMAX_BASE_URL`、`MINIMAX_MODEL`

优先级：MiniMax（若配置）→ Kimi。缺 Key 则启动失败。
